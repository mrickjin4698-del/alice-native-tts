# R2.0 — 首段可听延迟与前导静音裁剪

## 结论

R2.0 的保守裁剪候选没有找到任何可安全删除的首段前缀：160 个候选测量的裁剪长度均为 0ms。首个 Callback 的 TTFA 中位数约 199–205ms；长句在该 Callback 中的阈值活动 PCM 晚 220–360ms。裁剪没有提前首个活动 PCM，也没有稳定改善 RTF 或完整合成耗时。**拒绝启用该裁剪策略，Chunk 24 默认行为保持不变。**

长句的低活动段不能据此认定为可删除的前导静音。已有 R1.9 波形检查显示，低能量信号从首样本附近就已出现；其后才有精确零值区间。删除零值区间会越过已经出现的弱信号或跨过内部停顿。没有人工盲听和真实播放验收，因此本轮不作音质通过结论。

## 模型加载诊断

此前的 Cargo 构建运行器在首次创建 ORT Session 时停住，尚未进入 ONNX 图加载。相同运行器在显式设置 `ORT_DYLIB_PATH` 指向工作区已有的 R1.1 ORT 1.30 / CUDA 13 DLL 后，最小 CUDA smoke 通过，CUDA Frontend、GPT Encoder/Step、VITS 及 CPU 参考会话也全部加载完成。DLL 文件版本为 `1.30.0.20260909.3.f2c39fe`，全模型加载约 5.84s。该现象是运行时 DLL 路径配置问题；不能把此前的挂起归因于模型图损坏或模型体积。

复现配置使用 `target/r1.1-ort130-cuda13/native/onnxruntime.dll` 作为 `ORT_DYLIB_PATH`，并将同目录和 Torch CUDA DLL 目录加入 `PATH`。设备为 NVIDIA GeForce RTX 5070 Ti 16GB，驱动 610.74。R2.0 基准选用 CUDA Frontend、GPT、流式 VITS；CPU token sampling、ABI-1、固定随机种子 1234 和 Chunk 24 不变。诊断模式仍允许 Frontend、GPT Encoder 和 VITS 的已审计 CPU 辅助节点；本轮没有记录逐节点 EP 分配，因此不声称这些图的每个节点都在 GPU 上运行。GPT Step 保留既有严格 GPU 放置规则。

## 方法

- 语料：中文短句、含多音字中文短句、中文长句、含多音字中文长句、英文短句、英文长句、中英短句和中英长句。
- 每组、每策略 30 次预热 + 20 次测量，共 480 次预热和 320 条测量记录（160 组 A/B 配对）。
- A/B 顺序在测量阶段交替。两种策略走相同合成、语义生成、VITS 解码和 Chunk 24 路径；候选只检查并裁剪首个 PCM Callback。
- 裁剪条件：连续前导窗口 RMS ≤ `1e-7`、峰值 ≤ `1e-6`，至少 100ms；保留检测起点前 80ms，实际裁剪至少 20ms。内部静音不处理。首活动参考阈值为两个连续 10ms 窗口 RMS ≥ `1e-3`。
- 队列仿真采用 32ms 和 64ms 预缓冲；它是 Callback 时间线仿真，不等同实际设备播放验收。
- RTF 按未裁剪生成音频时长计算，避免把缩短输出样本数误报为推理加速。

四个长句的阈值活动 PCM 相对首个 Callback 分别延迟约 220ms（zh_long）、270ms（zh_poly_long）、360ms（en_long）和 260ms（mixed_long）。A/B 的活动时刻基本相同，符合零裁剪结果。Callback TTFA 的小幅上下波动没有稳定方向；候选完整耗时和 RTF 也没有一致改善。

对 R1.9 基线 Chunk 24 的首个 Callback WAV（PCM16 导出）复查：`zh_long` 首个 10ms RMS 约 `3.33e-5`，前导段没有全零窗口；`zh_poly_long`、`en_long`、`mixed_long` 的首个 10ms RMS 分别约 `2.06e-5`、`4.51e-6`、`1.53e-5`，均从首窗口就含非零样本。之后才分别出现约 140ms、230ms、140ms 的连续全零窗口。全零区段位于起始弱信号之后，属于 Callback 内部间隙；不能通过裁剪首部安全移除。振幅来自 PCM16 导出，存在量化，但非零首窗和零段位置可直接核验。

## 一致性与播放检查

- 320/320 测量均完整结束且输出有限值；160/160 A/B 配对的语义 Token 数、首段 Token 数、Chunk 数、完成状态和输出样本数一致。
- 当前公开合成 API 不导出 Token ID 序列；因此这里只核对 Token 数量和音频/Chunk 形状，并确认裁剪没有改动采样或模型调用路径，不声称做过 Token ID 逐项比较。
- 160 个裁剪候选都实际裁剪 0 个样本；波形对齐检查 0 组不匹配，裁剪后最大绝对差 `2.98e-7`。由于候选没有裁剪，波形差异只是重复 CUDA 合成的数值差，不代表裁剪质量通过。
- 32ms、64ms 队列仿真均未出现 underrun；候选运行中的最小模拟余量约 104.95ms。
- 人工盲听：未执行。真实音频设备播放：未执行。两项都不能由数值相似度或仿真替代。

匿名盲听包取每组每策略的首个测量结果，共 16 条；轨道 ID 已打乱，策略映射单独保存在包外的 `blind-key.json`。即使继续人工试听，本候选没有实际裁剪音频，故无法用它证明提前可听收益。

## 决策与后续

拒绝该全局首段静音裁剪候选，不减少起音保护区、不降低门限来追求更多裁剪。要继续降低长句首次可听延迟，应先对首个 Callback 的低能量区作逐样本、ASR 和人工听辨，确认弱辅音/自然停顿边界，再评估是否存在真正从 PCM 第一个样本开始的安全静音段。当前最稳妥的行为仍是保留原始首段音频和 Chunk 24。
